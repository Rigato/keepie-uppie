## O que entrou

- Repositório Git + GitHub Pages publicado por GitHub Actions (build, typecheck e testes antes do deploy).
- Vite 7 + TypeScript 5.9 + Phaser 3.90, tudo estático, caminhos relativos e zero recurso externo.
- Shell de escala: mundo fixo **540 × 1080** (1:2), canvas centralizado; colunas laterais no desktop; safe area e sem scrollbar.
- Cenas `Boot → Title → Play` e máquina de estados com retry preparada.
- `PlatformService` com `FallbackAdapter` (localStorage + memória) e `StorageService` com schema versionado (`keepie.save.v1`): melhor score, moedas totais e mute.
- Áudio sintetizado via WebAudio (sem arquivos), com unlock no primeiro gesto.
- Overlay de debug (`?debug=1`), `?resetSave=1` e `?slow=` para inspeção.
- Rótulo de build visível no canto inferior (fase · versão · sha) para confirmar o que está publicado.

## Como testar

1. Abra a URL no celular e no desktop.
2. Confira o título, o **BEST** e o rótulo `F0 · 0.1.0-dev · <sha>` no rodapé.
3. Toque/clique para entrar: a cena de jogo mostra a bola de demonstração e o HUD (0 m / 0 moedas). Ainda **não há chute** — é F1.
4. Abra `?debug=1`: painel com FPS, build, save e botão **RESET SAVE**.
5. Recarregue: se o melhor score mudou via debug ou partida futura, ele persiste.
6. Gire o celular e teste em janela estreita: sem scrollbar, sem corte.

## O que NÃO é bug nesta fase

- Bola parada/animada e HUD zerado: o core loop entra em F1.
- Colunas laterais sem conteúdo dinâmico: o shell é só enquadramento até F6.

## Notas técnicas

- Base de escala 1:2 é o limite aceito pelos portais e mantém ângulos idênticos entre telas.
- `PlatformService` já tem boot com timeout; a Bridge da Playgama só entra na publicação, sempre vendorizada na versão mais recente (registrar versão + hash).
- Storage: nada de `localStorage` direto no gameplay; toda leitura/escrita passa pelo adapter.
