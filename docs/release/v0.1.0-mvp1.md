## O que este build é

O MVP1 completo do GDD: um arcade vertical de embaixadinha, um input, mobile-first. O jogador toca a bola em queda, o ângulo é oposto ao ponto de toque, a força vem da velocidade de encontro e a altitude em metros é o placar. Obstáculos perturbam (nunca matam), interativos dão propósito à rota, dois powerups mudam o momento e o streak puxa a próxima run.

## O que está dentro

- **Core:** chute só em queda, ângulo oposto, força com piso, whiff neutro, câmera-catraca, paredes, morte por queda, retry em 1 toque, altitude + moedas + melhor score local.
- **Obstáculos:** hard (reflete), soft (drena), breakable (estilhaça acima de 1400 u/s), birds/bando (desvio leve), spawner por altitude com mix crescente.
- **Interativos:** moedas em trilha, argolas com burst de 8, molas que lançam a 2650 u/s, pickups de powerup.
- **Powerups:** Magnet (15 s, só moedas, re-pega reinicia) e Aimed Shot (arma sem prazo, mira de 2 s, timeout com força média).
- **Skill:** Perfect Touch, streak `NICE → GREAT → ON FIRE`, febre de 8 s com moedas x2.
- **Meta/plataforma:** save versionado (com fallback memória), mute persistente, pausa, auto-pausa, build em um ZIP com `index.html` na raiz, caminhos relativos e zero recurso externo.

## Validação desta build

- **64 testes unitários** em 8 arquivos: chute, câmera/altitude, colisão, save, spawner de obstáculos, spawner de interativos, streak e mira.
- **Smoke E2E 7/7**: boot → título → Play → chute → morte → save → retry, sem erro de console (`npm run test:e2e`).
- **Pacote em subpasta:** ZIP extraído em `/sub/` e servido por HTTP; o smoke passou 7/7 e o Network só teve requests locais.
- **Layout:** sem scrollbar/corte em 390×844, 907×510, 800×450, 1216×684, 1280×720 e 1920×1080; rotação preserva a cena.
- **Network:** zero request externo além do próprio host; áudio 100% sintetizado, sem arquivo.

## Decisões que o playtest precisa confirmar

- **Janela de reação da catraca** (âncora 45%, ~0,8 s de queda visível) e a gravidade reduzida do primeiro saque.
- **Densidade e mix de obstáculos**: a subida está vazia demais ou saturada? 190→115 m é o ponto de partida.
- **Janela do Perfect** (±16%): ~1 em 5 chutes bons ou fácil demais?
- **Tiers intermediários do streak**: hoje NICE/GREAT são rótulos; só a febre multiplica moedas. Se o playtest pedir, viram multiplicador.
- **Aimed Shot**: a pausa é "carta na manga" ou freio? O arrasto no dedo precisa de ajuste?
- **Magnet**: raio/duração dão suco sem virar modo de jogo?

## Limitações conhecidas

- **Desktop portrait-first:** em iframe 16:9 o jogo fica estreito (255 px em 907×510; 360 px em 1280×720). O HUD não corta, mas fica pequeno. Um layout desktop largo é decisão pós-MVP.
- Arte geométrica de placeholder e SFX sintetizados; sem música (pós-MVP).
- Aimed Shot foi validado com mouse; o arrasto em dedo real ainda não foi medido.
- Auto-pausa por visibilidade não tem teste automatizado.
- Sem SDK de portal (Playgama/CrazyGames) nesta build: storage é o fallback local. Ao publicar na Playgama, vendorizar a **Bridge mais recente** e registrar versão + hash.
- Reiniciar pela pausa descarta a run atual (moedas dela não vão para o total).

## Como gerar de novo

```bash
npm ci
npm run typecheck
npm test
npm run test:e2e     # com um preview em :4173
npm run package      # build + validação + ZIP + manifest em release/
```

O manifest (`release/manifest.json`) registra versão, data, tamanho, SHA-256, contagem de arquivos, maior path e a lista de paths. O ZIP contém o **conteúdo** de `dist/`, não a pasta.

> O rótulo de build no rodapé do ZIP gerado localmente mostra `dev` no lugar do SHA; no CI/Pages ele mostra o SHA do commit. O conteúdo de jogo é o mesmo.
