## O que entrou

- **Pausa** de verdade: botão no canto superior direito (área de 64 u ≈ 46 px), cena `PAUSED` com **RESUME**, **MUTE/UNMUTE** e **RESTART**. `ESC`/`P` também resume.
- **Mute persistente**: o estado vai para o save (`muted`) e é aplicado no boot; o áudio também suspende sozinho com a aba oculta.
- **Auto-pausa** ao trocar de aba/minimizar: volta com a cena de pausa, não com a bola caindo.
- **Rastro da bola** (6 fantasmas, 220 ms) para leitura de velocidade.
- **Hit-stop de 40 ms** no Perfect: o impacto tem peso sem atrapalhar o ritmo.
- **Tela de morte** com `+N coins` e jingle curto quando é novo recorde.
- **Smoke E2E** (`npm run test:e2e`): boot → título → Play → chute → queda/morte → save → retry, com falha em qualquer erro de console.

## Como testar

1. Toque no botão **II** no canto superior direito: o jogo pausa, a cena aparece e o botão **MUTE** desliga o som.
2. Recarregue: o mute precisa continuar desligado.
3. Troque de aba e volte: o jogo deve voltar **pausado**.
4. **RESTART** deve começar uma run limpa (0 m, sem streak).
5. Gire o celular: o canvas reajusta e a run continua.
6. Abra em 907×510, 1280×720 e 1920×1080: sem scrollbar, sem corte, HUD sem sobreposição.

## Ferramentas

```bash
npm run dev          # servidor local
npm run test:e2e     # precisa de um preview em :4173 (ou BASE_URL=...)
```

`scripts/smoke.mjs` usa `playwright-core` e um Chromium do sistema (`CHROME_PATH` ou `/usr/bin/chromium`, `chromium-browser`, `google-chrome`). Ele usa `?debug=1` para ler o estado da cena; é um gate de desenvolvimento, não roda no deploy do Pages.

## Decisões técnicas

- A pausa é uma **cena separada** (`Pause`) com a `Play` pausada pelo SceneManager: o mundo congela, o input da pausa continua vivo e o restart é limpo.
- O botão de pausa é uma `Zone` de 64 u e a cena ignora toques nessa área, para pausar nunca virar kick/whiff.
- O mute é aplicado no `AudioBus` e persistido no save; o estado do áudio não depende do portal.
- E2E roda local: o CI de Pages continua com typecheck + testes + build (rápido e estável); o smoke é rodado antes de release.

## Limitações conhecidas

- **Desktop portrait-first**: em iframe 16:9 a área jogável fica estreita (255 px em 907×510; 360 px em 1280×720). O HUD não corta nem sobrepõe, mas fica pequeno. Em 1920×1080 o jogo renderiza 540×1080 (1:1). Um layout desktop largo é decisão pós-MVP.
- Sem música (pós-MVP); o vocabulário de sons está completo para as interações atuais.
- Auto-pausa por visibilidade não foi exercitada em teste automatizado (só o caminho manual).
- O smoke depende de `?debug=1` e dos nomes dos campos da cena; renomear campos quebra o script (falha explícita).
